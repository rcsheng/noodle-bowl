Design Proposal · 2026.05.25

Players don’t know what shields are, or why they should care about their streak.

Both mechanics are central to the social loop — but right now they appear as a 13 px emoji in the masthead and a 2.2 second toast. This doc tears down how Duolingo solves the same problem, extracts what we steal (and what we don’t), and proposes seven new surfaces tailored to a weekly-cadence editorial product.

AuthorClaude (design) StatusDraft — pre-PRD Targetalpha-v0.4.0 candidate Effort~1 release
TL;DR

Add seven just-in-time education surfaces around the existing streak / shield mechanics. No mechanic changes. Lean on a “shields are gifts from friends” framing — the social DNA is the differentiator.

  • ProblemThe system works, but it’s invisible. New players never form a mental model of what a streak is worth or how a shield gets earned.
  • ApproachDuolingo’s pattern: short story-card modals at the exact moment each concept becomes relevant, never upfront.
  • RiskModal fatigue. We mitigate by capping at one modal per session and using inline banners for the rest.

03  ·  Design principles

Six constraints we’ll hold the new surfaces to.

Every proposed screen later in this doc traces back to one of these. If a surface can’t justify itself against this list, it doesn’t ship.

1

Teach only what’s about to happen.

No mechanic gets explained until the player is one tap away from using it. The shield primer fires the first time the user opens “Ask a friend.” Not before.

vs. a first-launch tutorial that everyone skips.
2

Shields are gifts, not insurance.

Every shield in the system was earned because another human answered a question for you, or accepted yours. Foreground that. The hero copy is “Mei gave you a shield,” not “you earned a shield.”

vs. Duolingo’s “your streak might die” framing.
3

One modal per session, max.

If two education moments would fire in one session, the second downgrades to an inline banner. Modal fatigue kills retention faster than poor education.

vs. back-to-back takeovers.
4

Visible cap, visible slots.

Wherever a shield count appears, show the empty slots too. The mental model has to be “I have n of 3” — not just “I have 1.” Empty slots create gentle pull without nagging.

vs. a bare numeral that conveys no progress shape.
5

Weekly rhythm, not daily anxiety.

This is a weekly product. The streak language stays calm. No countdowns, no flame multipliers, no “practice now or else.” Late-week nudges read as reminders, not threats.

vs. Duolingo’s heat-of-the-moment urgency UI.
6

Anon users get the same education, different ending.

Don’t hide the lesson behind a sign-up wall. Show the full primer to guests — the sign-up ask comes only after they’ve earned something worth keeping.

vs. the current pattern where the educational copy is glued to the upsell.

⑧   Tappable masthead chip

The smallest surface, made educational.

Today’s 🔥 3 🛡 1 chip becomes: a flame count + a mini slot row (filled = shield, outline = empty). It’s now a tap target; tapping opens a tooltip with a one-sentence status + a link to Stats.

06  ·  Shield iconography

Three options for the shield mark itself.

All of the mocks above use option B. Pick a direction before we land any of this; the choice flows through every other surface.

🛡
A. Emoji 🛡
Status quo
ProsZero work. Renders everywhere. Universally legible.
ConsSystem emoji clashes with the editorial type system. Renders differently on iOS / Android / web. Reads as “casual game” rather than “newspaper.”
B. Monoline shield
Recommended · used in mocks
ProsCustom SVG, matches the accent color. Reads at any scale. Slot empty/filled states are clearly distinct. Pairs cleanly with the existing 4 px inner-border treatment.
ConsAdds an SVG asset to maintain (still ~30 lines).
C. Engraved monogram
Newspaper–maximal
ProsStrongly on-brand. Feels like a printer’s mark. The italic N ties to the masthead.
ConsHard to read empty/filled state at thumbnail sizes. Could look fussy in the slot row. Probably better reserved for the milestone celebration.

Recommendation: ship with B (monoline) as the working icon throughout the app, and reserve C (engraved monogram) for the streak-milestone celebration where the typography can breathe. Drop A entirely — the cross-platform emoji rendering is the worst part of the current surfaces.

07  ·  Open questions

Things to settle before this becomes a PRD.

Each of these is a small decision with downstream consequences. Marking them now so they don’t turn into “we’ll figure it out in implementation.”

Q1
What’s the cap on shields visible in the slot UI?

The reducer caps internal shields at 12. But the slot row visualizes 3. Do we hard-cap at 3 in the data model, or keep 12 internally and visualize the first 3 + a “+9” chip? Recommend: visualize 3, allow up to 3 in the model. More than 3 cheapens each one.

Q2
Does the “at-risk” nudge ever fire for week-1 players?

If a player just started Monday, should Saturday show them the at-risk banner? Recommend: no — only fires once a streak ≥ 2 weeks exists. Otherwise it’s a guilt trip about a one-week habit they haven’t formed yet.

Q3
Anonymous “first shield earned” flow — what’s the CTA?

Three options: (a) same modal, primary CTA is “Sign up to keep it”; (b) same modal, dismiss reveals the sign-up banner inline; (c) skip the modal entirely for anon, route straight to the existing ShieldSignUpBanner. Recommend (a) — the gift framing is too valuable to skip.

Q4
What does “Tell me more” do on the streak-ignition modal?

Two options: opens a 2nd card that previews shields (chain-teach), or scrolls down inside the same modal. Recommend: 2nd card — matches the dot pattern, and most users will tap the primary CTA without ever seeing it.

Q5
Milestone celebrations: which weeks?

Duolingo celebrates 7, 14, 30, 50, 100, 365. Weekly cadence suggests 4, 12, 26, 52. Recommend small embellishment (gold inner border + engraved shield icon at the top) rather than a separate modal — the existing celebration already fires every week.

Q6
Should the shield primer block the “Ask a friend” flow?

If the player taps Ask, sees the primer, and dismisses — do they end up on the share sheet or back on the question? Recommend: primary CTA proceeds to the share sheet; “Not now” returns to the question. The primer is education during the action, not before it.

Q7
How do we track which user has seen which surface?

Today the gameReducer holds streakSavedBannerSeen, showStreakCelebration, etc. Recommend a single onboarding map: { streakIntroSeen, shieldPrimerSeen, firstShieldEarnedSeen, firstShieldSaveSeen }. Persisted via the same AsyncStorage + Firestore merge path as existing flags.

Q8
Push notifications for at-risk?

CLAUDE.md says push notifications are “permanently deferred.” So — in-app banner only for now, optional re-evaluation later. Worth noting that the at-risk banner only helps players who already open the app on Sat/Sun.

Next

If this direction lands, here’s the path to PRD.

  1. Review with team — circulate this doc, settle Q1–Q8, pick an icon direction.
  2. Trim or expand — if scope is too big, surfaces ⑥–⑧ can land in a follow-up release. The four modals (①–④) + at-risk banner (⑤) are the minimum viable education set.
  3. PRD update — fold the agreed surfaces into the v0.4.0 PRD as a new section: “Streak & Shield Onboarding.”
  4. Tasks — break out per-surface so they can ship incrementally behind a feature flag.
